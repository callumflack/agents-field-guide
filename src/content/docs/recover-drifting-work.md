description: Find where the work first diverged and choose a repair you can check.

When the same miss keeps coming back, compare what you asked for with the first artifact or action that took the work somewhere else.

| What you see | What to do |
| --- | --- |
| One clear change with an obvious check | Ask for the edit and the check. Keep the rest of the work in place. |
| Several plausible designs and an unsettled choice | Ask to see the same task in two or three alternatives side by side. Choose what to keep before asking for implementation. |
| An agreed requirement keeps disappearing | Find the first handoff, edit, or check that dropped it. Preserve the parts that work and name one repair and the evidence that would settle it. |
| The same call keeps failing across different inputs | Inspect a real error. Try one request with the intended settings before sending the whole batch. |

Ryan Singer compares four designs against the same product stories so you can see what each interface lets a person do and what happens behind it. [Four design options side by side](/four-design-options-side-by-side/).

For example, suppose you asked for an export that a customer can open and the agent keeps returning a screenshot of a success message. Check where “opens the exported file” became “shows the success message.” Keep the existing UI and ask for one check that opens a real export and inspects its contents.

For a failure that only showed up after inspecting the underlying records, see the [AgentsView field report](/agentsview-learning/). For the next check after a repair, see [Prove the thing the user can actually do](/prove-the-user-outcome/).
